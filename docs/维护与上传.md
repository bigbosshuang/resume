# 作品集维护与上传

## 上传哪些文件

将 `GitHub作品集` **文件夹内的内容**放到 GitHub 仓库根目录：

```text
README.md
assets/
  previews/     # GIF 动态预览
  videos/       # H.264 MP4 演示视频
  images/       # 已确认可公开的补充界面与点云图；隧道图为脱敏版
docs/
  维护与上传.md
.gitignore
```

在 GitHub 网页创建仓库后，通过 **Add file → Upload files** 上传这些文件和文件夹，再提交。根目录中的 `README.md` 会作为仓库介绍显示。也可以解压交付的 ZIP 后上传其中内容。

若要放进已有仓库的 `portfolio/` 子目录，将以上文件作为整体放入该子目录即可，相对链接仍然有效；在仓库主 README 中增加 `[我的作品集](portfolio/README.md)` 入口。

不要只上传 `README.md`：GIF 和视频需要一并上传，保持原目录结构。

**若已经上传过旧版，请同时删除仓库中的内部素材，而不是只替换 README。** 本版仅恢复用户确认可公开的 `双目球机.mp4` 及其 GIF。含内部控制台的 `双目摄像头2.mp4` 及其衍生画面继续排除；所有重复静态图也不打包。更新 README 不会自动删除远端旧文件。如果内部数据曾提交到公开仓库，删除当前文件不等于清除历史记录，需要另外处理相关提交历史与附件。

## 视频的显示与处理

- GIF 使用仓库内相对路径，可以直接显示；点击 GIF 可打开对应的完整 MP4。
- MP4 使用相对链接，点击后打开文件页；没有播放器时可下载播放。
- 若希望 README 中直接出现视频播放器，可将允许公开的 MP4 拖入仓库的 Issue 编辑框，等待附件上传完成，把获得的实际附件地址单独放在一行。
- 当前版本用 GIF 提供页面内动态展示，不依赖附件地址或 HTML `<video>` 标签。
- 保留的五段视频采用 H.264、20 fps、无音轨，并前置播放索引；所有视频均控制在 9 MB 以下。
- 四个项目共提供五段短 GIF：工业五金缺陷检测包含软件界面、设备现场两段，其余项目各一段。GIF 不代表完整实验流程。

## 后续增加作品

1. 先确认素材可公开，检查画面是否包含内部信息、账号、密钥、个人信息或不宜披露的数据。
2. 将演示视频放入 `assets/videos/`，需要时增加 `assets/previews/` 动态预览；已有视频的项目不再重复堆放同画面静态图。用户明确补充的业务界面或三维数据等不同模块，可放入 `assets/images/`，配清晰图注和职责边界。
3. 在 README 的导航表中增加入口，并按固定顺序新增章节：**项目背景 → 我承担的工作 → 关键技术 → 演示**。
4. 个人职责按模块描述，区分独立负责、参与开发与团队系统效果；量化结果只写有依据的数据。
5. 检查链接与播放效果，更新 README 页尾日期，并确认上传包不含过时或内部素材。

可后续补充光声内窥设备、国产 AI 芯片部署的演示，以及隧道项目经过公开审核的视频。隧道项目现有脱敏界面展示，没有编造视频入口，也没有把其他项目的技术参数移用过来。
